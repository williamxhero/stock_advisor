# 分配评测事实、推导、裁决与策略写入权

评测与进化中心采用“来源事实 → 版本化推导 → 治理裁决 → 专属执行器”的单向权限链，不建立一个能够读写所有状态的中心对象。

| 领域对象 | 权威所有者 | 允许的写入 | EvaluationObservatory 的权限 |
| --- | --- | --- | --- |
| 周期、阶段、工具、重试、发布与失败执行事件 | 实际执行动作的 Companion 运行时组件 | 追加不可变事实；必要时由原组件产生纠正事件 | 读取、校验完整性和引用 |
| 阶段资格判定 | EvidenceGate 及同类确定性资格门 | 记录带规则版本、输入引用和原因的通过或拒绝 | 读取并作为合格交付口径；不得自行判定合格 |
| 判断快照与 T+1/T+3/T+5 后验 | JudgmentLifecycle 及结果核验器 | 冻结判断、登记到期检查和核验结果 | 读取并形成判断结果维度 |
| 评测快照与预测快照 | EvaluationObservatory | 追加带输入水位、算法版本和 `as_of` 的不可变推导 | 创建和查询；不得覆盖来源事实 |
| 进化实验与候选比较 | EvaluationObservatory 维护评测记录；EvolutionGovernance 拥有状态裁决 | Observatory 追加比较证据，Governance 改变实验治理状态 | 比较、估计成熟度、提出建议；不得晋升 |
| 治理裁决 | EvolutionGovernance | 在版本化治理政策内记录继续观察、淘汰、请求选择、晋升或回滚 | 只读 |
| 日程版本 | ScheduleRegistry | 通过验证、乐观并发和不可变 revision 修改未来周期 | 只读并提出候选；不得直接更新 |
| 阶段预算、搜索广度、来源组合与模型路由策略 | 各自的版本化策略服务 | 执行获准裁决并写策略执行回执 | 只读并提出候选；不得绕过策略服务 |
| 用户确认 | 桌面应用经本地 Gateway 提交的明确命令 | 对超出自动授权边界的裁决作批准或拒绝 | 展示依据，不代替用户确认 |

LLM 可以解释数据、提出候选或生成面向用户的说明，但不是执行事实、资格判定、评测推导、治理裁决或生产策略的权威写入者。桌面 UI 也只展示投影和提交明确命令，不直接修改业务数据库。

所有派生对象必须引用来源对象及版本：评测快照保存事件水位与评测器版本，预测快照保存预测时点与模型版本，治理裁决保存采用的评测快照和治理政策版本，策略执行回执保存原策略版本、新策略版本及幂等键。新事实或新算法通过追加新版本表达，不追溯改写历史。这样可以独立重建评测、校准历史预测、审计自动进化，并保持当前“运行时是业务状态唯一写入者、日程注册表是日程唯一生效来源”的架构边界。
