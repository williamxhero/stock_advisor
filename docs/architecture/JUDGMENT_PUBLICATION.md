# 正式判断发布

M1 v5 / M2 v4 使用 `judgment_publication.py` 的共享流水线；M0 继续只做客观观察。旧版本仅保留历史读取兼容。

冻结证据先生成判断内核：具体基准情景、置信度、周期、最多三个事实—机制—含义链、最强反证、组合动作、最多两只真实持仓重点与双向失效条件。证据引用与数值锚点由代码检查，事实支持、风险、推理及表达质量另用独立语义审查。来源身份、字段齐全或出现“我认为”均不构成质量通过依据。

只有通过审查的内核才可存入带输入哈希的恢复检查点。正文调用只接收内核，不新增研究或改变决策；其独立审查须同时绑定内核与正文哈希。内核最多三次，表达最多两次，受原阶段绝对截止时间约束。

表达失败时，仅连接已经审查的内核语句；无合格内核则保持待修复，不生成通用行情模板、不标记完成。M1 子调用继续禁止 H0；M2 审查可读取本轮 H0/M1。风险规则版本随输入冻结。影子评测与正式检查点隔离。

后续审查若确认正文忠实于内核但事实依据不成立，该内核即失去发布资格；其拒绝审计同时阻止重启恢复。仅能在本轮剩余的三次内核、两次表达额度和原截止时间内重新研判；不得靠改写措辞或旧检查点重新发布同一内核。

研判修复携带上一份未发布候选与累计批评，不覆盖先前反馈。多调用链使用旧 M1 重试的整轮时间范围，仍由任务的正式发布时间封顶；并非把每个内部调用都压缩进原来一次调用的时间。

模型子调用分别记录审计、用量和错误，父阶段保留发布链引用，不重复累计子调用成本。已发布历史消息不重写。

模型上下文对重复证据正文去重，不截断来源正文。当前行情判断不把检索到的既往 AI 长篇回复当作生成范例；核验知识保持可用，周期复盘仍保留原判断用于结果对照。完整冻结输入留在审计记录中。检查点同时绑定生成、审查与上下文投影策略，不能跨策略变更复用。

回归入口：`tests/runtime/test_judgment_publication.py`。发布必须继续执行全量测试、干净提交构建、安装版本校验与正式新请求语义验收；单次模型审查通过不等于用户质量验收通过。
