# 伴生研判 UI 名称约束

状态：canonical；2026-08-25 由用户确认。

本文件冻结 AI Decision Center 主界面及后续讨论使用的名称。主界面是三栏工作台：从左到右依次为“今日列表”、“AI 消息”和“我的消息”。“当前判断”是三栏共同上下文，不是独立面板。

“AI 消息”和“我的消息”保持 3:2 固定宽度比例；“今日列表”保持导航宽度。窗口缩放不能改变两者比例。

## 顶部与全局控件

应用窗口标题栏显示“A股 AI Decision Center”；主界面顶部左侧只显示当天日期，不重复应用名称或“最新回复”。顶部右侧依次为运行状态提示、“持仓”和“开机启动”。

“持仓”打开单实例非模态窗口。窗口只展示事实持仓、参考行情、最近变更和撤销入口；内部股票研究状态不是持仓 UI 合同。旧行情必须显示时间口径。

## 今日列表与历史列表

“今日列表”是左侧当日研判周期列表。正式 Codex 自动化消息与伴生 cycle 是不同链路，正式消息不得冒充 M0、M1 或 M2。

每项使用自然状态文案：`等待触发`、`已排队`、`AI 研究中`、`等待提交 H0`、`正在生成 M1`、`正在生成 M2`、`AI 判断已完成`、`AI 未启动`、`未按时运行`、`AI 运行失败`。异常使用克制的红色提示。

“历史列表”位于左侧第二页签：

- 按日期树形分组，日期默认收缩；
- 搜索是唯一筛选入口；
- 子项只显示短任务名称，不显示冗长正文；
- 字体使用应用前景色，不使用黑色。

## 当前判断

用户在“今日列表”选中的一个研判周期。切换后，AI 消息、我的消息、待提交消息、输入框草稿和语音归属全部切换，不得串入其他周期。

## AI 消息

主界面中间区域是一条属于当前判断的连续时间线，不再使用固定的 M0、M1、M2面板。

- M0、M1、M2是独立里程碑消息，使用小型标签和开始/完成时间；
- 普通聊天、故障说明和判断修订按时间穿插；
- 顶部仅保留轻量锚点 `M0`、`M1`、`M2`、`最新`和“朗读”；
- 锚点只滚动到对应消息，不切换数据源；
- 不把里程碑拼成一篇 Markdown 报告；
- AI 使用自然、口语化、理性但非机械化的表达，不在正常交流中反复陈述数据口径；
- 只有错误、故障或盲区足以改变判断时，才自然说明原因和影响。

朗读默认读取当前选中消息；没有选择时读取最新 AI 消息。用户阅读旧内容时，新消息不得强制滚到底部。

## 我的消息

主界面右侧显示当前判断中的用户消息，分为待提交和已提交两种状态。

### H0 锁定前

- `发送`把输入框内容加入待提交区并清空输入框；待提交消息可单条撤回；
- `提交 H0`原子提交全部待提交消息；没有待提交消息时表示不评论；
- AI 在 H0 锁定前不回复；
- 到自动截止时只提交待提交区，绝不提交输入框草稿；
- 输入框草稿、待提交消息和语音状态均按当前判断独立保存。

### H0 锁定后

- `发送`仍把输入框内容加入待提交区；
- 第二个按钮显示`提交`，一次提交整个消息批次并最多触发一次 AI 回复；
- 已提交消息不可删除，只能追加修正；
- 普通聊天草稿永不自动提交；
- H0 锁定后的消息不追加到 H0，也不进入原始 M2输入。

持仓处理、H0冻结、聊天回复和正式经验入库只在`提交 H0`或`提交`后发生。待提交消息撤回后不产生业务事件。

若消息包含成交、持仓、成本、仓位或资产事实，其下方可显示“正在识别持仓信息”“持仓已更新”“需要补充”或“未作为真实成交处理”。不显示 JSON、task_key 或 Cycle ID。

## 输入与语音

语音状态固定为 `Idle → Recording → Transcribing → Idle/Error`。录音和转写期间输入框只显示波形、不可编辑，发送和提交按钮不可用。转写结果以换行追加到录音开始时所属任务的输入框草稿，不覆盖原文，仍需用户点击发送和提交。

## 全局滚动条契约

所有窗口、方向和滚动区域必须复用 `ThinScrollBarStyle`：竖向宽度 2 DIP，横向高度 2 DIP，背景透明，无方向按钮，悬停不变宽。禁止新建第二套滚动条模板。

WPF 的 `ScrollViewer`、`ListBox`、`TextBox` 等内部模板会用系统参数覆盖普通隐式样式，因此应用资源还必须统一覆盖 `SystemParameters.VerticalScrollBarWidthKey` 和 `SystemParameters.HorizontalScrollBarHeightKey`，并由唯一 `ThinScrollViewerStyle` 负责内部滚动条模板。UI 契约测试必须实例化真实 `ScrollViewer`、`ListBox` 和 `TextBox`，验证其内部纵横滚动条，而不能只测试一个裸 `ScrollBar`。发布前同时验证调试输出与正式 publish 产物，避免旧二进制造成视觉回退。
