# 历史功能记录：历史列表运行时投影迁移

来源聊天：`修复历史列表日期与计数`（线程 `01a04055-2195-7cc3-aa35-43ca915da8af`）  
记录时间：2026-08-27  
最后已知状态：标题计数和选中态样式已修复；历史数据源从旧缓存迁移到运行时投影仍是后续工作。

## 问题根因

历史列表当时读取的是旧的本地消息缓存，其中只有 8 月 24、25 日的记录；8 月 26 日的伴生研判已存在于运行时主库，却未被投影给该旧列表。因此这不是日期筛选错误，而是读了迁移前的数据源。

## 目标链路

```text
运行时主库
  -> exchange/to-client 的版本化历史投影 JSON
  -> 桌面历史列表
```

桌面端不应直接写或读取业务主库。运行时是事实唯一写入者；桌面通过版本化接口提交幂等命令、读取只读投影并续传事件。

## 迁移计划

- 运行时提供按日期/游标查询历史投影的版本化接口，并维护稳定的事件序列。
- 桌面端通过统一 Gateway/Exchange adapter 请求 `GetHistory(date/cursor)`，而非扫描旧 SQLite 缓存或大量文件。
- 桌面端仅缓存 UI 状态、草稿和读取游标；缓存不能成为业务历史的事实来源。
- 断线后从最后事件序列续传；命令携带 `command_id`，重试不重复执行。
- 保留旧 adapter 仅作迁移兼容；迁移完成后停止将其作为实时主链路。

## 已完成的小范围修复

- 移除了历史列表标题中的记录计数。
- 修复了树控件选中态的前景/背景对比，保证选择后仍可读。
